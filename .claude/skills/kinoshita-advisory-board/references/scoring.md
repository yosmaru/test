# 事業計画 完成度スコアリング

伴走の各回で、事業計画がいまどこまで固まっているかを点数とレーダーチャートで可視化する。目的は二つある。一つは、事業者に「前回より進んだ／まだ空いている」を一目で伝え、宿題を出して提出するモチベーションを維持すること。もう一つは、事業計画書を出せる水準に達したかを客観的に判定することである。

点数は事業者を安心させるためのものではない。むしろ「まだ25点しかない」という現実を突きつけ、次に何を埋めれば点が上がるかを示す装置である。甘い採点は伴走の価値を殺す。裏付けのない仮定に高得点を付けてはならない。

## 8つの評価軸

事業計画の完成度を、次の8軸で採点する。各軸は協議会の視点に対応する。

1. 顧客・需要（マーケティング）— 誰が、なぜ、いくら払うのかが実在で裏付けられているか
2. 商品・価格・利益率（マーケティング・企業戦略）— 何を売り、粗利がいくら残るかが詰まっているか
3. 体制・担い手（組織マネジメント）— 誰が回すのか、人を採れるのか、続くのか
4. 収支・資金（ファイナンス）— 収支計画と資金構成が実数で組まれ、撤退ラインがあるか
5. 物件・立地（不動産・立地）— 立地の磁力と物件の法的健全性が確認されているか
6. 権利・法務（法務・権利）— 名義・契約・許認可が紙で固まっているか
7. 行政・許認可（行政）— 必要な手続きと所要期間が工程に織り込まれているか
8. 戦略・リスク（企業戦略・全視点）— 競争優位とリスク・撤退基準が言語化されているか

案件によって関係の薄い軸（例: 物件を持たない事業の「物件・立地」）は、採点対象から外し、レーダーの軸数を減らしてよい。無関係な軸を0点のまま残すと総合点が不当に下がる。外した軸は明示する。

## 採点の基準（各軸 0〜100点）

証拠の強さで採点する。事業者の熱意や計画の丁寧さではなく、「その数字・事実が、現場の裏付けを持っているか」で測る。

- 0点 未着手。情報がない、まだ考えていない
- 25点 仮定のみ。方向性や希望はあるが、裏付けがゼロ。「たぶん貸せる」の段階
- 50点 一部実データ。相場・ヒアリング・公開統計などで部分的に裏付けが取れている
- 75点 実データで裏付け。現場の一次情報（成約事例、テスト販売、見積書、登記確認など）で検証済み
- 100点 検証済み＋整合。裏付けがあり、かつ他の軸の数字と矛盾なく整合し、そのまま事業計画書に載せられる

25点刻みを基本とし、中間（10点、40点など）を付けてもよい。付けた点の根拠を必ず一言添える。「顧客・需要 25点：移住者を想定しているが、実際に借りたい人の確認はまだゼロ」のように書く。

## 総合スコアと完成度段階

総合スコアは、採点対象とした軸の単純平均（案件により重み付けしてもよいが、その場合は重みを明示する）。総合スコアを完成度段階に対応させる。

- 0〜25点 骨格段階。顧客・カネ・体制が仮定だらけ
- 26〜50点 収支検証段階。骨格は埋まり、収支と資金の裏付けを取る段階
- 51〜75点 資金調達段階。数字が実数化し、金融機関・出資者と話せる段階
- 76〜100点 計画書化可能段階。全軸が裏付けを持ち、対外用の事業計画書を出せる

事業計画書の作成に進めるのは、総合80点超、かつ全採点軸が50点以上に達したときである（`references/business-plan-template.md` の80点ルール）。この条件を満たした協議録では、「いまの事業の完成度」セクションで「『事業計画書にまとめて』と言っていただければ簡易事業計画書に統合します」と必ず告知する。総合点が高くても特定の軸が50点未満なら、そこが計画の穴になるので、計画書化の前にその軸を埋める宿題を優先する。

## モチベーション設計（宿題と点数を連動させる）

各回で次を示すと、宿題を提出する動機が働く。

- 今回の総合スコアと、前回からの伸び（例: 前回32点 → 今回47点、+15）
- レーダーチャート（今回を塗り、前回を線で重ねて、どの軸が伸びたかを見せる）
- 出した宿題のそれぞれが、どの軸を何点上げる見込みか（例: 「宿題1〜3を終えると『顧客・需要』が25→75点、総合はおよそ+12点」)
- 計画書化可能段階まであと何点で、それには何を埋めればよいか

点が上がったことは率直に認める。伴走は減点法ではない。ただし、上がっていない軸から目をそらさせない。伸びた軸を認めたうえで、次に伸ばすべき軸を名指しするのが、この採点の使い方である。

## レーダーチャートの出力

`scripts/radar_chart.py` を使ってSVGのレーダーチャートを生成する。スコアをJSONで渡すと、8軸（または採点対象軸）のレーダーを描く。前回スコアを渡すと、前回を点線で重ねて進捗を可視化する。

使い方:

```
python scripts/radar_chart.py --scores scores.json --output radar.svg
```

scores.json の形式:

```json
{
  "title": "案件名（第N回）",
  "axes": [
    {"name": "顧客・需要", "current": 25, "previous": 0},
    {"name": "商品・価格・利益率", "current": 40, "previous": 25},
    {"name": "体制・担い手", "current": 50, "previous": 50},
    {"name": "収支・資金", "current": 25, "previous": 10},
    {"name": "物件・立地", "current": 60, "previous": 25},
    {"name": "権利・法務", "current": 30, "previous": 0},
    {"name": "行政・許認可", "current": 40, "previous": 0},
    {"name": "戦略・リスク", "current": 35, "previous": 20}
  ]
}
```

`previous` は任意。初回は省略してよい。採点から外した軸は `axes` に入れない。生成したSVGは、協議録の「完成度スコア」セクションから参照するか、ユーザーに直接提示する。チャットにMarkdownで出す場合は、スコアの表とチャートの要約を添える。
